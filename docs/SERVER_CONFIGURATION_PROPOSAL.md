# Totem Lumen 伺服器設定檔企劃書

狀態：**第一階段已實作，遊戲內驗收待確認**。本文件同時保留完整設計與未完成的驗收項目；以下「提議介面」已作為第一版實作基礎。

## 目標與現況

讓伺服器管理員透過一個獨立檔案控制 RGB 玩法光照的運作模式、伺服器處理預算與手持光源，並能少量覆寫方塊光色。設定必須同時適用於獨立伺服器與單人世界的整合伺服器，不依賴客戶端 Vulkan，也不得讓玩家的畫質設定決定伺服器生怪規則。

既有三類世界資料包規則：方塊的 `emission_color`／`gameplay_strength`、生怪光譜感度、維度環境光。伺服器工作量與時間預算現在由伺服器設定快照提供，預設仍為 `20,000` 與 `2.0 ms`；客戶端的 `config/totem-lumen.properties` 仍只管本機畫面設定。

## 提議介面（第一版）

檔案：`config/totem-lumen-server.json`。首次啟動若不存在，產生附帶預設值的範例檔；檔案屬於伺服器實例，單人世界共用同一個遊戲實例的設定。需要各世界不同規則時仍使用各世界資料包，不偷偷複製設定進世界存檔。

```json
{
  "schema_version": 1,
  "gameplay": {
    "spawn_light_mode": "RGB",
    "work_budget_per_tick": 20000,
    "time_budget_ms": 2.0
  },
  "held_light": {
    "enabled": true
  },
  "block_overrides": {
    "minecraft:redstone_ore": {
      "emission_color": [1.0, 0.18, 0.06]
    },
    "minecraft:deepslate_redstone_ore": {
      "emission_color": [1.0, 0.18, 0.06]
    }
  }
}
```

範例中的紅石礦顏色與內建預設值相同，只用來展示管理員如何覆寫；實際生成的預設檔應使用空的 `block_overrides`，避免把內建值固定成無法隨版本更新的複本。

| 欄位 | 預設 | 語意 |
| --- | --- | --- |
| `spawn_light_mode` | `RGB` | `RGB` 使用伺服器光譜生怪判斷；`VANILLA` 恢復原版生怪亮度判斷，不改客戶端渲染 profile。 |
| `work_budget_per_tick` | `20000` | 所有維度共用的 RGB 工作量上限，不能變成「每維度各一份」。 |
| `time_budget_ms` | `2.0` | 所有維度共用的每 tick 時間上限；屬於處理期限，不是硬即時保證。 |
| `held_light.enabled` | `true` | 控制伺服器核准並傳送的手持視覺光源；關閉時發送空快照清掉既有手持光，不更改物品本身的原版發光材質。 |
| `block_overrides` | `{}` | 以完整方塊 ID 覆寫個別光源的 `emission_color` 與可選的 `gameplay_strength`。後者不得讓原本不發光的狀態變成光源；其現有客戶端影響見下方相容性註記。 |

第一版驗證範圍：`work_budget_per_tick` 為 `1,000..100,000`，`time_budget_ms` 為有限的 `0.25..5.0`；即使管理員調高工作量，仍由同一個全伺服器時間預算限制。仍需用壓力測試確認上限是否合適，不把此區間當成已量測的安全值。

第一版**不提供**無條件關閉整個 RGB 快取的開關：它不只供生怪判斷，關閉時還要處理其他玩法讀取者、未收斂區塊與重新啟用後的重建，不能用一個布林值直接跳過 tick。也不把客戶端陰影、GI、反射、亮度滑桿放進伺服器檔案。

## 規則優先順序與同步

每個欄位依序取「JAR 內的**預設資料包** → 世界資料包 → `block_overrides` 明確指定值」。預設資料包名為 `totem-lumen:default_lighting`，包含光色對照表、預設下界生物感度規則，以及 Minecraft＋RGB 方塊光畫面亮度 ×2／傳播衰減 ×1 的調整；載入時把光色展開成發光方塊的有效規則，其他資料包仍可用每方塊 JSON 覆寫。預設資料包可停用；停用後沒有其他規則的發光方塊改用中性白光；若沒有其他資料包提供同路徑調整，亮度與衰減倍率回到 ×1，不再暗中套回預設色表。覆寫是**逐欄位**合併：只指定顏色時，`gameplay_strength` 仍由資料包或方塊狀態決定。生怪感度與維度環境規則仍由資料包管理，第一版不在設定檔複製第二套格式。拒絕重複的方塊 ID；色彩各分量須為有限 `0..1`，玩法強度須為整數 `0..15`，資料包與設定檔合成後的規則總數不得超出現有封包的 `8,192` 筆上限。

合成後的**有效方塊規則**才送給相容客戶端；生怪模式與處理預算留在伺服器。RGB 客戶端仍自行計算視覺欄位，不傳輸逐格光資料。純原版 profile 不因伺服器 RGB 設定被強制改成 RGB。若未安裝相容客戶端，不應送出自訂封包或要求新增玩家端依賴。

**相容性註記：**舊版設計文件把 `gameplay_strength` 描述成「僅伺服器使用」，但目前 `LightingWorldRulesPayload` 確實序列化它，客戶端 RGB 光源預測會讀它，伺服器手持光源也會讀它。第一版設定檔應保持這個既有線上行為，並在設定說明標註它可能同時影響 Minecraft RGB 與手持光的強度；不能默默宣稱或改成 server-only。若日後要把玩法強度與視覺強度拆開，應另提帶遷移／協定相容策略的設計。

## 遊戲內「伺服器光照」檢視 UI

在 Minecraft 的**「畫面設定」→「顯示」**區段，加入「伺服器光照預覽」與「光照資料包」兩個入口；原版「資源包」按鈕保持原位。光照資料包頁採左右兩欄：左側可用、右側已啟用（越上方優先級越高），選取後以箭頭加入、移除、上移或下移。清單分頁不改資料包順序；每次實際變更才重新載入世界資料，且不重排無關的世界資料包。尚未進入世界或伺服器未提供資料時，預覽頁顯示「未連線／未提供」狀態，不冒充有效設定。

```text
畫面設定／顯示
[伺服器光照預覽…]  [光照資料包…]
```

所有玩家均可**唯讀查看**目前連線伺服器的有效設定；連線到遠端伺服器時，不能從客戶端修改伺服器檔案或資料包。預覽會列出伺服器回報的已啟用資料包（低優先級至高優先級）。選取某一包時，方塊頁列出所有可設定光源：包內既有規則顯示該包的值，尚未寫入該包的方塊顯示目前生效值並標記「未在此包設定」，以便新增規則；生怪／維度頁只列出該包提供的規則，亮度／衰減倍率亦顯示該包的設定。不選資料包時，顯示實際生效的綜合規則與倍率。某包未提供生怪或維度規則時，該類清單為空；上方生怪模式、手持光與工作預算仍是伺服器全域設定，不會因為選包而變成該包的設定。資料包清單與規則內容由伺服器提供，避免客戶端猜測。

單人世界可在「光照資料包」頁開啟該世界的 `datapacks` 資料夾，逐個啟用／停用 Totem Lumen 光照資料包並觸發世界資料重載。預覽頁的單一資料包選擇同時決定檢視內容與儲存目標：未選資料包時顯示綜合生效結果，修改後另建並啟用一個 `totem-lumen-lighting-<名稱>` 世界資料包，只寫入本次修改的規則；選取已啟用、由 Lumen 介面建立的資料包時，顯示該包的規則，修改後直接更新同一包，保留其他規則。多筆方塊 RGB／玩法強度修改先暫存，列項、色樣與詳情以黃色標示，按「儲存修改」後才寫入資料包並重新載入。更新既有包會先備份後替換，若資料重載失敗則還原。內建包、第三方包與 ZIP 包仍可檢視，但不能從此介面原地改寫；如需建立覆蓋層，可改選綜合結果。整個流程不修改 `config/totem-lumen-server.json`。伺服器設定檔中的明確覆寫優先於資料包，這類規則不能從預覽頁儲存來取代。畫面標題不用「伺服器光影」暗示伺服器執行 GI／陰影渲染：它顯示的是 RGB 玩法光照、手持光源授權與有效方塊規則。本機的 GI、陰影、反射與渲染 profile 留在原本的畫面設定。

隨 JAR 附帶但預設關閉的 `totem-lumen:double_light_test` 是測試資料包，可在同一頁直接切換。它的 `data/totem-lumen/totem_lumen/light_tuning.json` 將 Minecraft RGB 的**方塊光畫面貢獻**設為 2 倍，並將伺服器與客戶端共用的 RGB 方塊光傳播損失設為 2 倍；不調整天空光、手持光、原版 profile 或 Totem Vulkan 畫質。RGBA 欄位仍是 0–15，畫面通道也有飽和上限，所以已滿亮的方塊不可能再呈現精確 2 倍亮度。停用測試資料包後，若預設資料包仍啟用，倍率回到亮度 ×2／衰減 ×1；兩者都停用才回到 ×1／×1。若另有資料包提供同路徑設定檔，依一般資料包優先順序取最上層檔案。

| UI 分類 | 圖示 | 顯示內容 |
| --- | --- | --- |
| 方塊光源 | **對應方塊的實際物品／方塊圖示**，例如紅石礦、深層紅石礦、火把 | 方塊名稱與 ID、有效 RGB 色樣、`gameplay_strength` 或「依方塊狀態」、規則來源（內建／資料包／伺服器覆寫）。未發亮狀態仍標註不發光。 |

頁面先顯示總覽，再以「方塊／生怪感度／維度」分頁查看規則。點擊圖示或列項會顯示詳情；單人世界選中的方塊規則可進入暫存編輯頁，尚未存檔的修改跨搜尋與分頁保留。關閉時須再次確認才放棄暫存；若伺服器規則版本變動，禁止將舊暫存內容直接寫入新版本。後續仍需補譯名搜尋、來源篩選、排序與更完善的側欄式詳情版面。方塊規則可能很多，列表需只渲染可見列；沒有可用物品模型的方塊用明確的替代圖示和完整 ID，不顯示錯誤物品。圖示只是導覽線索，每項都要有文字、數值、色樣及 tooltip／旁白，並支援鍵盤焦點與小視窗版面。

**資料來源與生命週期：**預覽畫面只讀取伺服器權威快照，不能以本機 `totem-lumen.properties` 或預設色表冒充伺服器值。現有 `LightingWorldRulesPayload` 可供已有明示規則的方塊取得有效值，但不包含內建預設的完整清單、生怪模式、預算、手持開關和規則來源；實作時需要一份有版本、大小上限的伺服器設定摘要，詳細方塊有效值／來源及其他資料包規則則按需分頁請求，避免登入時複製龐大資料。加入世界、成功重新載入與設定變更後更新修訂版；跨服、換世界及斷線立即清除舊快照。未收到伺服器資料時顯示「未提供／尚未同步」，而不是顯示猜測值。封包不得包含伺服器檔案路徑、管理員資訊或其他私密內容；管理操作只在本機整合伺服器執行，不建立遠端修改封包路徑。

## 載入、重新載入與失敗處理

啟動時在伺服器生命週期讀檔、檢查 schema 和數值，建立不可變設定快照，再交給 tick／生怪／手持光源流程。磁碟讀取與解析不得發生在 tick 熱路徑。檔案缺失時建立預設檔；**檔案存在但無效時拒絕伺服器啟動／單人世界載入**，不可悄悄套用預設值，讓管理員誤認設定生效。

規劃管理員指令 `/totemlumen config reload`：先完整解析候選檔，成功後於伺服器執行緒原子替換快照；失敗保留上一份有效設定並回報欄位錯誤。指令需 OP 權限。既有 `/reload` 仍處理資料包；兩種重新載入最後都應重新合成有效規則、重建受影響的伺服器光源區域、同步新顏色並重送／清除手持光源。不可先發新封包再讓舊世界規則繼續運作，也不可同步做全世界重照。變更預算可直接於下個 tick 生效；變更方塊光色／強度則以現有有界佇列逐步收斂，未收斂區塊維持保守生怪規則。

## 實作切分

1. 建立 common/server 專用的設定 schema、解析器、預設檔產生器與不可變快照；保留 `schema_version` 供日後遷移。
2. 將 `ServerGameplayLightingManager` 的兩個常數改為讀取快照，但預設行為完全一致；完成數值邊界與多維度共用預算測試。
3. 在方塊世界規則與設定覆寫之間建立單一「有效規則」合成入口，供玩法欄位、手持來源與發給客戶端的封包共用，避免畫面與伺服器讀到不同顏色／強度；補齊目前文件與實際封包欄位的落差。
4. 加入 `RGB`／`VANILLA` 生怪判斷與手持光開關，驗證關閉時不留殘光，切回時可恢復；保持混入點與資料包規則的既有安全語意。
5. 加入管理指令、錯誤診斷、文件和遷移說明。
6. 加入有界的伺服器摘要／規則詳情同步和預覽 `Screen`，沿用 Minecraft 原生物品／方塊渲染與本地化文字；本機整合伺服器另提供資料包管理與方塊規則另存。最後進行獨立伺服器與單人整合伺服器測試。

## 驗收條件

- 無設定檔時自動產生範例，舊世界與舊客戶端設定的預設行為不變；獨立伺服器不載入任何 client/Vulkan 類別。
- 無效 JSON、未知 schema、非法色值／預算、重複 ID 的錯誤可定位；失敗 reload 不改有效快照。
- 設定檔覆寫、資料包覆寫、移除覆寫、`/reload`、設定 reload、加入／離開與跨維度，都讓伺服器有效規則和相容客戶端顏色一致；不需同步整個 RGB 體素欄位。
- 生怪 `VANILLA` 模式的判斷與原版一致；`RGB` 模式保留未收斂區域不允許利用殘舊黑暗生怪的防護。
- 手持光關閉後現有光源消失，重新開啟後恢復；主手、副手與三種渲染 profile 均需實機驗證。
- 「伺服器光照預覽」與「光照資料包」位於畫面設定的「顯示」區段；原版資源包按鈕仍可正常使用，在小視窗與各 GUI 縮放比例下不重疊、不裁切、不遺失鍵盤焦點。
- 單人世界能開啟該世界的資料包資料夾、切換光照資料包、跨頁暫存多筆方塊 RGB／強度修改，並以黃色辨識未存項目；未選資料包時能以修改過的規則建立新資料包，選取已啟用的 Lumen 自建包時能更新該包，保留其他規則且失敗可回復。內建／第三方包不被覆寫。遠端伺服器只提供唯讀預覽。
- UI 在單人、多人與三種 profile 下只顯示該伺服器的值；重載、切換伺服器、斷線、缺少相容伺服器模組時不殘留舊資料。方塊圖示與其他代表物品對應正確，搜尋／篩選／大量規則的捲動仍流暢，繁中／英文、小視窗與鍵盤／旁白可讀。
- UI 封包有版本、長度和請求頻率上限，且沒有遠端編輯或提升權限的途徑；不傳送本機畫面設定、路徑、截圖或逐格 RGB 欄位。
- 壓力場景量測多維度總 tick 成本、區塊載入與大量紅石燈變更；比較設定預算上下限，不用單次編譯通過代替效能證據。
